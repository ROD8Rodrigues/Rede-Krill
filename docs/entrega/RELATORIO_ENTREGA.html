2. IMPLEMENTADO, MAS NÃO VALIDADO

Estes itens têm código/config no repositório e testes de lógica, mas sem execução real do ambiente completo:

  • Dashboard/métricas com Prometheus externo: endpoints expostos; nenhum Prometheus configurado para consumir (sem infra nesta máquina).
  • MailHog/UI: perfil dev configurado; interface nunca aberta.
  • Code splitting com cache de navegador: build gera chunks (verificado no output), mas comportamento em navegação real com cache/HTTP2 do nginx não foi exercitado.
  • Swagger UI em produção: rota gated por perfil; não aberta em navegador contra prod.
  • Refresh rotativo sob concorrência de múltiplas abas: coberto por teste de um fluxo linear; cenário com duas abas simultâneas não reproduzido manualmente.

4. NÃO IMPLEMENTADO, COM JUSTIFICATIVA

  1. Rate limiting distribuído (Redis/banco) — o mecanismo atual funciona por instância; multi-instância não faz parte do escopo de deploy avaliado. Recomendado antes de escalar horizontalmente (ADR-010 e SECURITY_REPORT.md §11 registram a limitação).
  2. 2FA/MFA e recuperação por e-mail — fora do escopo do desafio; exigiria backend de envio confiável (SMTP) e decisões de produto não levantadas. A troca obrigatória + política de senha cobre parte do risco.
  3. UI para gestão da outbox de e-mail — visível apenas via métricas/banco; prioridade menor que telas operacionais. Todos os estados estão no banco e na métrica Prometheus.
  4. Compatibilidade com empresa de navegadores antigos (IE/legados) — build moderno (esbuild/rolldown) sem polyfills deliberadamente; público interno.
  5. Clean de histórico do Git para segredos antigos — o histórico remoto é público e pertence ao repositório do usuário; limpeza de histórico (git filter-repo) exige decisão e execução pelo dono do repo (docs a indicam; não executada por isso).
